### 🔴 ここだけは崩さないこと

**JavaScriptは「動きを足す」だけで、「隠す」ことは絶対にしない。**

素のCSSでは全要素が見えている状態にしておき、`reveal` クラスが付いた時だけ CSSアニメーション（`animation-fill-mode: backwards`）で出現を演出している。だから **JSが止まっても・observerが動かなくても・アニメーションが無効でも、中身は必ず読める。**

最初の実装は逆（既定で `opacity:0`、JSが見えるようにする）で作ったが、**動きが止まった環境で本文がまるごと消えた**。入居者向けページには緊急連絡先が載っているので、演出より確実に読めることを優先する。同じ理由で、`<details>` の閉じた見た目も `html.js` が付いている時だけ有効にしている（JSが無ければ `<details>` の素の動作でそのまま読める）。

## 方針

- 検索エンジンには載せない（全ページ `noindex` ＋ `robots.txt` で `Disallow: /`）。
- リポジトリは public（GitHub Pages の無料プランの制約）。載せてよいのは各棟の掲示板に貼ってある水準の情報だけ。**入居者の氏名・部屋番号・個人の連絡先は絶対に置かない。**
- 画像は WebP に変換して置く（元画像は残さない）。

## 更新のしかた

ファイルを直して `git push` するだけ。1〜2分で反映される（保存と公開が別だったGoogleサイトと違い、押し忘れは起きない）。

**直すときに一緒に直すもの（漏れやすい順）**

1. **🔴 3棟ぶんある。** 全棟共通の内容（電話番号・緊急連絡先・ビン缶のページ）を直すときは `famille3/` `famille2/` `laville/` の**3つとも**。
2. **同じ本文がホームと個別ページの2か所にある。** 例：ゴミ出しの本文は `index.html` の `<details id="gomi">` の中と `gomi.html` の両方。**1棟あたり2か所×3棟＝6か所。**
3. **`search.js` の `SEARCH_INDEX`。** ここを直さないと、直した文言が検索に出てこない（ページ自体は壊れない）。棟ごとに別ファイル。
4. **電話番号は1ページに複数ある。** 問い合わせバー・フッター・`kinkyu.html` の本文。
5. フッターの `このしおりの最終更新日` と、ホームのお知らせ（**日付のあとに何を変えたかを一言添える**）。
6. `style.css` と `effects.js` は**3棟に同じものを配ってある**（共有していない）。デザインを変えたら3つともコピーし直す。
