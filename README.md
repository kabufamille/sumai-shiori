2026-09-07 に現行サイトから中身を引き写して作成し、同日公開。

**入口ページ（`/sumai-shiori/`）から各棟へは進めない。** けんじ方針＝「棟ごとのQRからアクセスした時だけ、その棟が開く」。各棟のURLを直接開くか、QRを使う。

**QR画像**：`デスクトップ/住まいのしおりQR_新URL/`（棟ごとに素のPNGと名前つきPNG。誤り訂正レベルH・980px）。**中身は実際にデコードして一致を確認済み。**

**掲示物**：`poster/` に3棟ぶんのA4 PDF。`G:\マイドライブ\住まいのしおり\住まいのしおり（縦）\` にある**現行の掲示物のQRだけを新URLに差し替えたもの**（レイアウト・写真・文言は一切変えていない）。元のPDFはそのまま残してある＝**旧QRは現行Googleサイトを指しており、そちらもまだ現役だから。**

- QRの訂正レベルは**元と同じM**にした（元は29×29マス・訂正M）。新URLのほうが長いので33×33マスになるが、印刷34mm角で1マス1.03mm＝元の1.17mmとほぼ同等。**1年運用できている条件を変えないための選択。**
- 差し替えは PyMuPDF の `page.replace_image(xref, ...)`。**差し替える前に対象xrefをデコードして旧URLであることを毎回確認**し、保存後に**300dpiで描画し直してからデコード**して新URLと一致することを確かめている（＝刷った状態に近い検証）。

### 🔴 検索避けは `noindex` だけが効いている

`robots.txt` はドメインの一番上（`kabufamille.github.io/robots.txt`）しか読まれないので、**このリポジトリの `robots.txt` は検索エンジンには無視される**（2026-09-07に404を実測）。ファイルは残してあるが、実効性があるのは**全ページの `<meta name="robots" content="noindex">`**。ページを増やすときは必ず入れること。

### 🔴 ここだけは崩さないこと

**JavaScriptは「動きを足す」だけで、「隠す」ことは絶対にしない。**

素のCSSでは全要素が見えている状態にしておき、`reveal` クラスが付いた時だけ CSSアニメーション（`animation-fill-mode: backwards`）で出現を演出している。だから **JSが止まっても・observerが動かなくても・アニメーションが無効でも、中身は必ず読める。**

最初の実装は逆（既定で `opacity:0`、JSが見えるようにする）で作ったが、**動きが止まった環境で本文がまるごと消えた**。入居者向けページには緊急連絡先が載っているので、演出より確実に読めることを優先する。同じ理由で、`<details>` の閉じた見た目も `html.js` が付いている時だけ有効にしている（JSが無ければ `<details>` の素の動作でそのまま読める）。

## 方針

- 検索エンジンには載せない（全ページ `noindex` ＋ `robots.txt` で `Disallow: /`）。
- リポジトリは public（GitHub Pages の無料プランの制約）。載せてよいのは各棟の掲示板に貼ってある水準の情報だけ。**入居者の氏名・部屋番号・個人の連絡先は絶対に置かない。**
- 画像は WebP に変換して置く（元画像は残さない）。

## 更新のしかた

**HTMLは手で直さない。正本は `_source/gen_sites.py`** ＝ここから3棟ぶんのHTMLと `search.js` を生成している。

```
python _source/gen_sites.py     # 3棟を作り直す
git add -A && git commit && git push
```

push から1〜2分で反映される（保存と公開が別だったGoogleサイトと違い、押し忘れは起きない）。

**どこを直すか**

| 直したいもの | 場所 |
|---|---|
| 3棟に共通する本文 | `gen_sites.py` の共通定数（`KANEN` `SODAI` など） |
| 1棟だけの本文 | `BUILDINGS` の中の、その棟の辞書 |
| 電話番号・最終更新日 | 先頭の定数（`KANRI_TEL` `KINKYU_TEL` `UPDATED`）。1ページに複数出るが定数は1つ |
| お知らせ | 3棟共通は `NEWS_COMMON`、1棟だけは その棟の `news_own` |
| 10月からのプラスチック改定 | `CHANGE_NOTICE` → `CHANGE_NOTICE_AFTER` に差し替え（1か所で3棟6か所に効く） |
| 見た目・画面の動き | `style.css` / `effects.js`。**これだけは生成対象外**なので `famille3/` を直して他2棟にコピーする |

**🔴 お知らせ（更新情報）の決まり**

- 入居者に関係する内容を直したら、**必ず `NEWS_COMMON` か `news_own` に1行足す**。日付は `"YYYY-MM-DD"`。
- 表示は日付の新しい順に **`NEWS_SHOW`（＝6）件だけ**。古いものは書き足すたびに自然に落ちる。**リストからは消さない**（後から見返せるように）。
- 見出しは「何を直したか」が分かる言い方にする（例：「〜を追加しました」）。
- **画面の使い勝手だけの手直しは載せない。** お知らせが操作の話で埋まると、ごみの分け方の変更のような大事な報せが埋もれるため。

**⚠️ 手でHTMLを直してしまったときは、次の生成で消える。** 直したい内容は必ず `gen_sites.py` 側へ。

**🔧 ローカルで確かめるときの罠**：`python -m http.server` はキャッシュ制御を返さないので、`effects.js` を直しても**ブラウザが古い版を動かし続ける**ことがある。挙動が変わらないときは、一時的に `window.SHIORI_BUILD="…"` のような印を埋めて**動いている側に名乗らせる**か、ポートを変えて立て直す。
